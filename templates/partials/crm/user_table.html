{% comment %} The user table -- the swappable region inside #user-table, re-rendered by every create / edit / password / status / delete action. Two kinds of row. Env-managed users (APP_AGENTS) show an "Entorno" badge and no actions: they are defined outside the app, so nothing here could change them and the buttons would only lie. DB users get the full set -- edit, new password, deactivate/reactivate, delete -- except that the row for *you* has no deactivate or delete, since locking yourself out is never what anyone meant. Deactivated users stay listed (muted, below the active ones) because they still name the conversations they answered; "Reactivar" brings them back. A third state, "Sin contraseña", is a ghost: an agent removed from APP_AGENTS whose mirror row remains. Setting a password adopts it as a database account; deleting it is the other way out.
